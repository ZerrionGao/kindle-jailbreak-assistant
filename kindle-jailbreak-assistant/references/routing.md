# 动态官方路由与引导审查

本参考只定义如何取得和复核当前路线；不提供静态型号、固件、按钮或越狱操作清单。KindleModding 是社区维护的上游技术资料，不是 Amazon 官方支持。搜索引擎摘要、论坛转述和旧博客只能帮助发现页面，不能替代上游原始内容。

## 当前上游入口与优先级

每次新会话都按此顺序刷新，并保存四份原文、最终 HTTPS 地址、获取时间和 SHA-256：

1. `https://kindlemodding.org/models.json`：精确型号、设备码和已知字段；
2. `https://kindlemodding.org/jailbreaks.json`：候选方法与适用条件；
3. `https://kindlemodding.org/jailbreakFinder.js`：上游向导的当前选择语义；
4. finder 当前选出的**具体方法页**：实际触屏文本、动作顺序、成功标记和载荷来源。

四份来源中任一份未完成显式确认前，不得命名自动化策略、创建占位文件或写入载荷。先以 `models.json` 与 `jailbreaks.json` 得到暂定路线，再抓取 finder 和具体方法页交叉复核；它们并列组成当前决定依据，不能只信其中一份。

## 每次刷新的最小检查

对每一份来源依次确认：

1. 请求和最终重定向地址都是 HTTPS；
2. 最终主机与当前上游入口或方法页允许的主机一致，没有悄悄跳到镜像、广告或未知下载站；
3. 内容非空，能以当前预期的 JSON、脚本或页面形式读取；
4. 关键语义没有缺字段、冲突或无法解释的页面改版；
5. 原始字节的 SHA-256 已记录，四份来源都由用户或会话流程显式确认。

不得执行 `curl | sh`。若当前方法只能触发远程脚本，先保存当时脚本快照和哈希，并向用户说明远程内容仍有时间差风险；用户触发前不得运行。

## 精确识别与三态提问

只用已探测到的精确型号、完整设备码和数字化固件版本做比较。不要根据“Paperwhite”“5.18 左右”、相近设备码或相邻固件猜测；缺少精确值时停在只读识别阶段。

注册、广告等条件只能记录为：

- **是**：有当前可观察证据；
- **否**：有当前可观察证据；
- **未知**：没有可靠证据或用户不确定。

若当前路线依赖某个未知条件，一次只问一个问题。例如：“当前方法需要确认设备是否已注册。请只回答：设置页面是否显示已注册的 Amazon 账户？” 收到可观察答案前，不提下一个问题，不猜测答案。

## 引导审查模式

下列情况进入只读的“引导审查模式”：上游页面结构或语义变化、四份来源不一致、模型/固件信息不完整、方法未知、最终下载主机改变，或安全策略无法对应当前方法。

此模式只允许：保存原始来源和哈希、报告冲突、读取当前方法页、要求用户提供一个可观察信息，或等待维护者澄清。不得复用旧缓存作为成功结论，不得按旧教程复制载荷，也不得尝试最接近固件。

未知方法只能阅读和记录，不能创建载荷写入。特别是 **SpringBreak 不使用普通 filler**；只有当前上游四来源和具体方法页明确允许的步骤才能继续，且普通占位策略在该方法下保持禁止。

## 面向用户的路线报告

报告路线时只报告已证实的现状，而不是复制教程：

```text
当前阶段：路线复核
正在做什么：已刷新四份 KindleModding 社区上游来源，正在核对它们是否指向同一方法页。
已完成：<精确型号、数字固件、来源 SHA-256 或“尚无”>
还差什么：<一个来源确认、一个三态问题或方法页成功标记>
是否需要你操作：<仅一个可观察动作；没有则“否”>
停止是否安全：安全；尚未写入 Kindle。
```

具体按钮文字和操作顺序必须从本次抓取的具体方法页实时转述。成功证据不从自然语言关键词自动推断：`method-policies.json` 只保存已审查的安全允许列表，路线确认时必须把当前页面实际声明与该列表取交集，并用结构化参数明确记录人工确认；页面未声明、列表未允许或两者冲突时保持只读阻断。
